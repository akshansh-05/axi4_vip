# AXI4 Memory-Mapped Verification IP (`axi_mm_vip`)

## 1. VIP Architectural Overview

The `axi_mm_vip` package models and verifies full-duplex, memory-mapped bus communication adhering to the **ARM AMBA AXI4 Protocol Specification (ARM IHI0022H)**.

Within the DMA verification platform, this VIP connects to the master memory interface of the DMA controller (`m_axi_*`), supporting two distinct verification roles:
1. **Active Slave Responder (DMA Standalone Mode):** Operates as a reactive memory slave, acknowledging Write Address (AW) and Write Data (W) beats, generating Write Responses (B), accepting Read Address (AR) requests, and supplying Read Data (R) bursts with randomized backpressure delays.
2. **Passive Monitor (Subsystem Mode):** Passively snoops physical bus transitions between the DMA master and the synthesizable on-chip SRAM (`axi_ram`), reconstructing burst transactions for scoreboard verification without driving bus pins.

The VIP is partitioned into two specialized sub-agents:
* `axi_wr_agent`: Governs the Write Address (`AW`), Write Data (`W`), and Write Response (`B`) channels.
* `axi_rd_agent`: Governs the Read Address (`AR`) and Read Data (`R`) channels.

## 2. The Transaction Class (`axi_seq_item`)

The sequence item (`axi_seq_item.sv`) is the fundamental data abstraction in the testbench. It elevates cycle-by-cycle pin toggles into high-level, burst-oriented transaction packets representing complete AXI4 read or write operations.

### 2.1 Randomized Transaction Fields (`rand`)

The following fields define the stimulus parameters generated by sequences or test cases:

| Field Name | Type | Width / Range | Protocol Role & Microarchitectural Purpose |
| :--- | :--- | :---: | :--- |
| `trans_type` | `rand axi_trans_type_e` | 1 bit (`AXI_READ`, `AXI_WRITE`) | Directs transaction processing to write or read driver/monitor paths. |
| `id` | `rand bit [ID_WIDTH-1:0]` | Parameterized (Default 8 bits) | Maps to `AWID` (write) or `ARID` (read) to track out-of-order burst contexts. |
| `addr` | `rand bit [ADDR_WIDTH-1:0]` | Parameterized (Default 16 bits) | Starting byte address of the burst transfer. |
| `len` | `rand bit [7:0]` | 8 bits (`0` to `255`) | Burst length representing $len + 1$ beats (1 to 256 beats per burst). |
| `size` | `rand bit [2:0]` | 3 bits (`0` to `7`) | Encodes number of bytes per beat: $2^{\text{size}}$ (e.g., `3'b010` = 4 bytes for 32-bit datapath). |
| `burst` | `rand axi_burst_type_e` | 2 bits | Burst type: `AXI_BURST_FIXED` (00), `AXI_BURST_INCR` (01), `AXI_BURST_WRAP` (10). |
| `data[]` | `rand bit [DATA_WIDTH-1:0]` | Dynamic Array `(len + 1)` | Payload data words for write bursts. Sized dynamically to match the burst length. |
| `strb[]` | `rand bit [STRB_WIDTH-1:0]` | Dynamic Array `(len + 1)` | Sparse byte write strobes (`WSTRB`), enabling byte-level write masking per beat. |
| `addr_delay` | `rand int unsigned` | Integer ($\ge 0$) | Number of idle clock cycles to inject before asserting `AWVALID` or `ARVALID`. |
| `data_delay[]` | `rand int unsigned` | Dynamic Array `(len + 1)` | Number of idle bubble cycles to inject before asserting `WVALID` on each beat. |

### 2.2 Sequence Item Constraints

To guarantee that randomized transactions strictly respect ARM AMBA AXI4 protocol rules, `axi_seq_item` implements five formal constraint blocks:

#### 1. Dynamic Array Sizing (`c_array_sizes`)
Ensures that data and strobe arrays match the number of beats for write transfers, while remaining zero-length for read transfers:
```systemverilog
constraint c_array_sizes {
    if (trans_type == AXI_WRITE) {
        data.size()       == (len + 1);
        strb.size()       == (len + 1);
        data_delay.size() == (len + 1);
    } else {
        data.size()       == 0;
        strb.size()       == 0;
        data_delay.size() == 0;
    }
}
```

#### 2. Physical Bus Width Sizing (`c_size_limit`)
Clamps beat transfer size to the exact width of the physical data bus ($size = \log_2(\text{STRB\_WIDTH})$):
```systemverilog
constraint c_size_limit {
    size == $clog2(STRB_WIDTH); // 32-bit bus: size = 2 (4 bytes/beat)
}
```

#### 3. 4KB Page Boundary Non-Crossing (`c_4kb_boundary`)
Per ARM AMBA AXI4 Section A3.4.1, an incremental (`INCR`) burst must never cross a 4KB address boundary. The constraint evaluates start address and total payload span:
```systemverilog
constraint c_4kb_boundary {
    if (burst == AXI_BURST_INCR) {
        (addr % 4096) + ((len + 1) * (1 << size)) <= 4096;
    }
}
```

#### 4. Wrapping Burst Rules (`c_wrap_rules`)
Per AXI4 specification, wrapping bursts must have a power-of-two length of 2, 4, 8, or 16 beats, and the start address must be aligned to the total burst size:
```systemverilog
constraint c_wrap_rules {
    if (burst == AXI_BURST_WRAP) {
        len inside {8'd1, 8'd3, 8'd7, 8'd15};
        addr % (1 << size) == 0;
    }
}
```

#### 5. Default Stimulus Distributions (`c_default_burst_distribution`)
Applies soft constraints to generate realistic stimulus without starving corner cases:
```systemverilog
constraint c_default_burst_distribution {
    soft len inside {[8'd0 : 8'd15]};     // Bias toward typical 1-16 beat bursts
    soft addr_delay inside {[0 : 3]};     // 0-3 wait cycles on address
    foreach (data_delay[i]) {
        soft data_delay[i] inside {[0 : 3]}; // 0-3 bubble cycles between beats
    }
    foreach (strb[i]) {
        soft strb[i] == {STRB_WIDTH{1'b1}}; // Default to fully enabled byte lanes
    }
}
```

### 2.3 Monitor-Sampled Fields (Non-Randomized)

The monitor captures the following fields from physical pin handshakes to record responses and perform protocol checks:

| Field Name | Type | Width / Range | Monitored Information |
| :--- | :--- | :---: | :--- |
| `bid` | `bit [ID_WIDTH-1:0]` | Parameterized | Write response transaction ID captured from the `BID` channel. |
| `bresp` | `bit [1:0]` | 2 bits (`OKAY`, `SLVERR`, etc.) | Write response completion status code captured from `BRESP`. |
| `rid[]` | `bit [ID_WIDTH-1:0]` | Dynamic Array `(len + 1)` | Read data transaction ID sampled on each beat from `RID`. |
| `rresp[]` | `bit [1:0]` | Dynamic Array `(len + 1)` | Read response status code sampled on each beat from `RRESP`. |
| `wlast[]` | `bit` | Dynamic Array `(len + 1)` | Observed `WLAST` pin state per write data beat (verified by monitor). |
| `rlast[]` | `bit` | Dynamic Array `(len + 1)` | Observed `RLAST` pin state per read data beat (verified by monitor). |

## 3. Driver Implementation (`axi_wr_driver` & `axi_rd_driver`)

The drivers translate sequence items into cycle-accurate bus handshakes. Both drivers support bidirectional operation: Master Driver mode and Slave Responder mode.

### 3.1 Write Driver (`axi_wr_driver.sv`)

#### Run Phase Architecture
The driver resets interface pins, waits for reset deassertion, synchronizes to the clocking block, and branches based on configuration:
```systemverilog
virtual task run_phase(uvm_phase phase);
    reset_signals();
    wait(!vif.rst);
    @(vif.wr_drv_cb);

    if (cfg.is_master) begin
        run_master();
    end else begin
        run_slave();
    end
endtask : run_phase
```

#### Master Driving Logic (`run_master` & `drive_master_write`)
When driving as an active master, the driver pulls transactions from `seq_item_port` and executes three parallel threads using `fork...join`:
* **Thread 1 (`AW` Channel):** Waits for `req.addr_delay`, drives address parameters (`awaddr`, `awlen`, `awsize`, `awburst`, `awid`), asserts `awvalid`, and holds until `awready` handshakes.
* **Thread 2 (`W` Channel):** Iterates through each beat $i \in [0, len]$. Injects `req.data_delay[i]` bubbles, asserts `wvalid`, drives `wdata` and `wstrb`, asserts `wlast` strictly when $i == len$, and waits for `wready`.
* **Thread 3 (`B` Channel):** Asserts `bready` and waits for `bvalid && bready`, capturing `bid` and `bresp` back into the sequence item before calling `item_done()`.

#### Slave Responder Logic (`run_slave`)
When operating as an active slave responder (the primary mode for DMA standalone verification), the driver concurrently executes three independent worker tasks:
1. **`slave_handle_aw()`:** Monitors `awvalid`. When asserted, records transaction metadata into an internal queue (`slv_aw_q.push_back(aw_info)`). If `enable_awready_stall` is set, injects a randomized stall of $N$ cycles (`$urandom_range(min_awready_delay, max_awready_delay)`) before pulsing `awready = 1` for 1 cycle.
2. **`slave_handle_w()`:** Holds `wready = 1` to accept streaming write data beats. Increments beat counters and tracks `wlast`. When `enable_wready_stall` is configured, periodically deasserts `wready` for $M$ cycles every $K$ beats (`wready_stall_period`), verifying that the DUT handles data backpressure without data corruption.
3. **`slave_handle_b()`:** Waits until an address transaction is queued and its corresponding write burst has completed (`slv_w_bursts_done > 0`). Pops `aw_info`, waits `cfg.bvalid_delay` cycles, asserts `bvalid = 1` with `bid = aw_info.id` and `bresp = OKAY`, and holds until the DUT acknowledges with `bready = 1`.

### 3.2 Read Driver (`axi_rd_driver.sv`)

#### Slave Responder Logic (`run_slave`)
In DMA standalone mode, `axi_rd_driver` acts as the memory supplier for DMA read operations:
1. **`slave_handle_ar()`:** Snoops `arvalid`. Applies optional randomized `arready` backpressure stalls, captures request parameters (`arid`, `araddr`, `arlen`, `arsize`), and queues requests into `slv_ar_q`.
2. **`slave_handle_r()`:** Pops pending read requests from `slv_ar_q`. For each beat $i \in [0, arlen]$:
   * Generates deterministic or memory-mapped read payload words (`rdata`).
   * Asserts `rlast` strictly on the final beat ($i == arlen$).
   * Injects optional pipeline bubble cycles (`enable_rvalid_stall`) to stress the DMA read engine's input skid buffering.
   * Awaits `rready` handshake before advancing to subsequent beats.

## 4. Monitor Implementation (`axi_wr_monitor` & `axi_rd_monitor`)

The monitors passively observe bus transactions strictly through input clocking blocks (`wr_mon_cb` and `rd_mon_cb`), eliminating race conditions and ensuring that signals are sampled at physical setup/hold clock boundaries.

### 4.1 Write Monitor (`axi_wr_monitor.sv`)

#### Run Phase Architecture
The monitor forks four parallel collection and assembly threads:
```systemverilog
virtual task run_phase(uvm_phase phase);
    wait(!vif.rst);
    @(vif.wr_mon_cb);
    fork
        collect_aw_channel();
        collect_w_channel();
        collect_b_channel();
        assemble_write_transactions();
    join
endtask : run_phase
```

#### Channel Snooping Tasks
* **`collect_aw_channel()`:** Samples whenever `awvalid && awready` are high on the clock edge. Records `awid`, `awaddr`, `awlen`, `awsize`, `awburst`, sample timestamp, and measured address wait states into queue `aw_q[$]`.
* **`collect_w_channel()`:** Samples whenever `wvalid && wready` are high. Pushes captured `wdata`, `wstrb`, and `wlast` into beat queue `w_q[$]`.
* **`collect_b_channel()`:** Samples whenever `bvalid && bready` are high. Pushes captured `bid` and `bresp` into response queue `b_q[$]`.

#### Transaction Assembly & Protocol Checks (`assemble_write_transactions`)
Assembles complete burst transactions from the decoupled queues:
1. Waits for `aw_q.size() > 0` and pops the address descriptor.
2. Instantiates a new `axi_seq_item` transaction item, populating address and burst attributes.
3. Loops $len + 1$ times to pop beats from `w_q`:
   * **In-Flight `WLAST` Protocol Check:** Asserts that the DUT drives `wlast == 1` strictly on the terminal beat ($i == len$). If `wlast` asserts early or fails to assert on the final beat, the monitor flags an authoritative UVM error:
     ```systemverilog
     if (i == desc.len && !beat.last)
         `uvm_error("AXI_WR_MON", "Missing WLAST on terminal burst beat!")
     if (i < desc.len && beat.last)
         `uvm_error("AXI_WR_MON", "Premature WLAST detected mid-burst!")
     ```
4. Pops the corresponding response from `b_q`, asserts that `resp.id == desc.id`, and broadcasts the assembled item via analysis port `ap.write(txn)`.

### 4.2 Read Monitor (`axi_rd_monitor.sv`)

* **Channel Snooping:** Decouples `collect_ar_channel()` (sampling `arvalid && arready`) and `collect_r_channel()` (sampling `rvalid && rready`).
* **Protocol Framing Check:** Enforces that `rlast` is asserted exclusively on beat $i == arlen$. Flags protocol violations if `rlast` occurs prematurely or is omitted.
* **Transaction Publication:** Broadcasts complete read transactions (address, length, data payload array, response codes) to `dma_scoreboard` and `dma_coverage` via `ap.write(txn)`.
